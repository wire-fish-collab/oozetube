# ウーズチューブ 3D流体シミュレータ

粘り気の高い液体が入った筒（ウーズチューブ／オイルタイマー）を、
スマホの傾きセンサーに連動させて再現するアプリ。`index.html` 1ファイルで完結する。

**液体と空気の両方を粒子として一緒に解いている。** 泡は作っていない。
空気が上がるのも、形が変わるのも、合体するのも、すべて計算の結果として出てくる。

- 容器はアクリル樹脂。角は丸めず稜線を立たせている
- 中身は「粘度の高い透明な液体」と「空気」の2つだけ
- 液体が穴から落ちると、下の空気が圧まり、ある時点で一気に抜ける（実物の周期と同じ）
- 傾けると、落下中の液も上がりかけの空気もその場で反応する

## 動かす

ファイルを直接開くだけでも動くが、**スマホのセンサーを使うには HTTPS での配信が必要**。
iOS は `file://` や `http://` では傾きを取れない。

```bash
python3 -m http.server 8411
# http://localhost:8411/ を開く（Macではドラッグで傾けられる）
```

**WebGPU が必要。** 計算も描画もGPUで行っている。

## 操作

| 操作 | 動き |
|------|------|
| スマホを傾ける・ひっくり返す | 重力が変わる |
| 画面をドラッグ / 矢印キー | 重力を傾ける（センサーが無いとき） |
| スペースキー | ひっくり返す |

## URLパラメータ

| 書き方 | 内容 |
|--------|------|
| `?debug=1` | fps・粒子数・相の交換量などを表示 |
| `?view=phase` | 液体＝青 / 空気＝橙 で塗り分け（物理の確認用）|
| `?view=gas` / `?view=liq` | 片方の相だけ表示 |
| `?seed=bubble` | 最初から液体の中に空気の塊を置く（浮力の確認用）|
| `?p=50000` | 粒子数を指定 |
| `?shape=hourglass` | 砂時計型（形を差し替える仕組みの確認用）|
| `?env=studio` / `room` / `sunset` | まわりの景色 |
| `?sim.viscosity=0.9` | `CONFIG` の数値パラメータを個別に上書き（調整用）|

## 中身

### 二相 Position Based Fluids

液体と空気の違いは**逆質量だけ**。浮力は与えていない。

- 拘束は**粒子の詰まり具合（数密度 Σ W）**にかける。質量を混ぜないので、
  液体の中に空気粒子が1個あっても無理な圧力が立たず、界面が安定する
- 位置の補正を**逆質量で重み付け**する。液体の圧力は深いほど高いので、
  下から押される量が上から押される量を上回り、軽い空気だけが昇る。これが浮力になる
- 相は添字で決まる（液体が前半、空気が後半）。途中で変わらないので並べ替えが要らず、
  描画では `firstInstance` を変えるだけで相ごとに描ける
- 凝集（表面張力）と人工圧力は**同じ相どうしだけ**。相をまたぐと界面で引き合ってしまう
- 粘りは全体の減衰ではなく **XSPH（粒子どうしの速度の均し）**で作る。
  せん断粘性なので、液が細く垂れるのも泡がゆっくり昇るのも同じ粘性から出てくる

**静止密度の基準は、初期配置の格子と必ず一致させること。** ずれていると
拘束がほとんど発動せず、圧力がまったく立たない（この取り違えで長く詰まった）。
`latticeFill` と `latticeDensity` は同じ単純立方格子を前提にしている。

### 通路（仕切りの穴）の寸法

液体が下りながら空気が上がる「すれ違い」が起きる必要があるので、通路には下限がある。

- `neck.holeRatio` を小さくしすぎると交換が完全に止まる
- `sim.cohesionLiq` を上げすぎると通路が栓になって止まる（2.2で停止を確認）
- `sim.iters` は閉じた容器では多めに要る（圧力が伝わるのに反復が必要）

容器が太いと空気の柱が切れる余地がなくなるため、`view.maxTubeAspect` で
太さに上限を設けている。柱は長さがその円周を超えないと切れない（Rayleigh-Plateau）。

### 描き方

- 液体と空気それぞれを球として深度に描き、**narrow-range filter** で平滑化する。
  範囲外のサンプルを捨てずに端へ丸めるので、粒のでこぼこだけ消えて輪郭は立ったまま残る
- 厚みは半解像度の加算バッファに貯め、Beer-Lambert で色を付ける
- 容器は符号付き距離関数をレイマーチし、アクリル・液体・空気の3媒質を統一的に扱う。
  界面ごとにフレネルで反射と屈折に分け、全反射のときは同じ媒質の中で反射させて追跡を続ける
- **環境マップには輪郭の硬い光源と細い縦のストリップを入れてある。** 容器が画面の
  大半を覆うので、見えているものはほぼ「容器ごしの環境マップ」になる。なめらかな
  グラデーションだけだと屈折させても何も見えない
- 背景は照明用の環境マップとは別に作ってある

### 容器の形を増やす

`SHAPE_BUILDERS` に1エントリ足すだけでよい。画面の比率と目標粒子数を受け取り、
`outer`（外形）と `cavity`（空洞）を返す。固体は outer から cavity を引いて導かれるので、
仕切り板は「cavity に含めない」だけで表現できる。

使えるプリミティブ:
`sphere` / `box` / `roundedCylinder` / `cone` / `torus` / `plateWithHole` / `revolve`、
演算は `union` / `sub` / `inter`（`k` で滑らかに）、どのノードにも `at:[x,y,z]`。

**`revolve` が一番使いやすい。** `(y, 半径)` の折れ線を回転させるので、
別のオイルタイマーの輪郭を数値の列として書くだけで試せる（`hourglass` が実例）。

## 性能

ソルバが時間の大半を使う。粒子数が実質の性能つまみ。
フレーム時間を見て描画解像度を自動で上下させ、30fps前後を保ちつつ余った分を解像度に回す。

M1 Mac / 縦持ち相当の画面で、5万粒子・25fps前後。

## 既知の制限

- WebGPU 専用
- 空気はまだ1個ずつの泡に切れず、塊で上がる
- 粘りや重さは、見た目を優先して調整した値。実際の粘度の数値ではない
- 液体は画面空間で合成しているため、屈折が大きく曲がる場所では液面の位置がわずかにずれる
- 泡が重なると手前の1個だけが描かれる（物理はすべて効いている）
- 画面の向きの補正（横持ち）は実機で未検証
